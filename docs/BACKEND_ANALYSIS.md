## 3. Known limitations re-verification
1. **Hardware-auth endpoints require JWT: PARTIALLY CONFIRMED (statement imprecise).** Create (`hardware_auth/views.py:36-37`) and complete (`:100-101`) require JWT (default auth). Detail, events and cancel (`:49,62,88`) accept SecureJWT OR the `X-Auth-Attempt-Capability` header (`authentication/authentication.py:67-81`), a single-attempt secret issued by the unauthenticated `POST /auth/preauth/` after username+password+device check. So a password-preauth capability holder with no JWT can report factors and cancel but not create or complete. Live: unauthenticated GET attempt detail returned 401 (consistent, does not discriminate).
2. **Factor reports recorded verified=false: CONFIRMED (source).** `hardware_auth/services.py:113-120` hard-codes `verified=False`; response hard-codes `"verified": False` (`views.py:82`); audit result "UNVERIFIED" (`services.py:123-129`); evidence classes CLIENT_ASSERTION / HOST_ASSERTION / UNAUTHENTICATED_SERIAL (`:17-22`). Not exercised live (POST).
3. **No challenge-bound verification / session issuance: CONFIRMED (source).** No nonce/challenge/device-signature fields in `FactorReportSerializer` (`hardware_auth/serializers.py:10-14`); `AttemptStatus` has no SUCCEEDED (`models.py:22-27`); `complete_attempt` always ends `FACTOR_VERIFICATION_UNAVAILABLE` and issues no token (`services.py:197-202`); preauth returns no JWT (`authentication/views.py:135-142`). Offline-policy issuance gated by `UNMET_ISSUANCE_PREREQUISITES` including `verified_authentication_evidence` (`offline_policies/services.py:36-41`).
4. **File-content endpoint 503: CONFIRMED in source, UNVERIFIED live.** Route `GET /api/v1/files/{file_id}/content/` -> `FileContentUnavailableView` (`storage/urls.py:16`, `storage/views.py:108-115`). It requires auth (401 otherwise), calls `get_file_for_content` (404 unless caller owns the file or has an active READ grant; admin role alone is not enough, `storage/services.py:62-73`), then unconditionally returns 503 `FILE_CONTENT_UNAVAILABLE` by design: no object storage/upload handler exists in this phase (`storage/views.py:1-6`; `FileMetadataSerializer.get_content_available` returns False). Live unauthenticated GET returned 401, so the 503 cannot be observed without credentials (no login attempted per instructions). Treat as "feature unavailable", not an outage. `POST /offline-policies/` is also always 503.

## 7. Desktop-client implications
- Only password login yields JWTs; hardware-only login is not possible server-side. Use `/auth/token/`, rotate refresh on each use (store the new refresh), `/auth/me/` for role (server is the role authority).
- Access token lives 10 min: refresh proactively; on 401 with code `token_revoked` / `role_changed` force re-login.
- Treat 503 `FILE_CONTENT_UNAVAILABLE` and 503 `OFFLINE_POLICY_ISSUANCE_DISABLED` as unavailable features, not retryable errors.
- Lists are paginated (`results`) except the grants list (plain array). Validate absolute `next` links same-origin.
- Register/login/preauth are throttled (429).
